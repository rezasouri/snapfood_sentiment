# مرحلهٔ اول: قرارداد خروجی و دادهٔ ارزیابی

هدف این مرحله فراهم‌کردن یک مبنای ثابت برای مقایسهٔ مدل‌هاست: همهٔ مدل‌ها باید خروجی یکسان بدهند و روی نمونه‌های مرجع یکسان سنجیده شوند. این مرحله مدل آموزش نمی‌دهد و دقتی برای اسنپ‌فود اعلام نمی‌کند.

## قرارداد استخراج

قرارداد نسخهٔ `1.0` در `src/snappfood_cx/contracts.py` و JSON Schema تولیدشده در `schemas/extraction.schema.json` قرار دارد. موضوع‌ها عبارت‌اند از:

| کد | معنی |
|---|---|
| `taste_quality` | کیفیت و طعم |
| `temperature` | دمای غذا |
| `packaging` | بسته‌بندی |
| `price_value` | قیمت و ارزش خرید |
| `delivery_delay` | تأخیر تحویل |
| `courier_behavior` | رفتار پیک |
| `portion_size` | حجم غذا |
| `missing_wrong_items` | اقلام ناقص یا اشتباه |

برای هر نظر، `review_id` و فهرست `records` برگردانده می‌شود؛ فهرست خالی هم معتبر است. هر رکورد موضوع، احساس (`positive`، `negative`، `neutral`، `mixed` یا `uncertain`)، عبارت شاهد، منبع برچسب، نسخهٔ مدل و وضعیت اعتبارسنجی دارد. بازهٔ شاهد با `start`، `end` و `text` مشخص می‌شود. انتهای بازه انحصاری و واحد آن Unicode code point در **متن اصلی** است، نه بایت یا متن نرمال‌شده.

تابع `validate_extraction` JSON، دسته‌های مجاز، شناسهٔ نظر و تطابق دقیق متن شاهد با بازه را بررسی می‌کند. وضعیت `validated` فقط درستی ساختار و ارجاع به متن را نشان می‌دهد؛ درستی معنایی موضوع یا احساس را اثبات نمی‌کند. اطلاعات اضافی و دسته‌های ساختگی رد می‌شوند.

## منابع ثابت و تبدیل برچسب‌ها

[ParsiNLU](https://huggingface.co/datasets/persiannlp/parsinlu_sentiment) از فایل‌های اصلی بخش غذا با commit ثابت `a3b08d0b93ca84e0017e2f490a2aa3ab36c79885` دریافت شده است. نسخهٔ کارت Hugging Face هم در فایل قفل ثبت شده است. [Pars-ABSA](https://github.com/Titowak/Pars-ABSA) از commit ثابت `4f71c10a4b84a52f38f4f35bbf84f4362b68d716` دریافت شده است. URL و SHA-256 هر فایل در `configs/benchmarks.lock.json` قرار دارد؛ اختلاف checksum اجرای آماده‌سازی را متوقف می‌کند.

- ParsiNLU: «طعم» و «کیفیت» به `taste_quality`، «بسته بندی» به `packaging` و «ارزش خرید» به `price_value` می‌رسند. هدف اصلی هر نمونه حفظ می‌شود. «ارسال» به «تأخیر» تبدیل نمی‌شود؛ «کلی» و «ارزش غذایی» هم کنار گذاشته می‌شوند.
- احساس خیلی مثبت/مثبت به `positive` و خیلی منفی/منفی به `negative` تبدیل می‌شود. خنثی و ترکیبی حفظ می‌شوند. برچسب `-3` به `absent` تبدیل می‌شود، نه خنثی؛ معنایش بیان‌نشدن احساس دربارهٔ موضوع پرسیده‌شده است.
- Pars-ABSA عمدتاً محصولاتی مثل موبایل را پوشش می‌دهد. همهٔ نمونه‌های سالم برای **احساس نسبت به هدف داده‌شده** حفظ می‌شوند، اما تنها نام‌های دقیق و مشخص مربوط به قیمت و بسته‌بندی، واجد ارزیابی موضوع‌های پروژه‌اند. کیفیت ساخت موبایل، کیفیت غذا فرض نمی‌شود.
- ParsiNLU بازهٔ شاهد ندارد. Pars-ABSA بازهٔ **نام موضوع** دارد که از جایگزین `$T$` بازسازی می‌شود؛ این بازه معادل عبارت شاهدِ احساس نیست. هفت نمونه با جایگزین ناقص/چندگانه کنار گذاشته شدند.

## نتایج آماده‌سازی واقعی

| مجموعه | آموزش | اعتبارسنجی | آزمون |
|---|---:|---:|---:|
| ParsiNLU، ردیف‌های موضوع‌محور مشترک | ۶٬۱۴۰ | ۷۶۰ | ۷۶۸ |
| Pars-ABSA، هدف‌محور عمومی | ۵٬۸۴۵ | ندارد | ۱٬۹۹۶ |

مجموع: **۱۵٬۵۰۹ نمونه**. در Pars-ABSA فقط ۲۰۳ نمونهٔ آموزش و ۶۵ نمونهٔ آزمون نگاشت مستقیم به موضوع‌های پروژه دارند. این مجموعهٔ کوچک برای ادعای کیفیت جامع کافی نیست.

۲٬۱۲۲ ردیف آموزش Pars-ABSA به متن‌هایی تعلق داشتند که در آزمون نیز دیده شدند؛ این ردیف‌ها از آموزش حذف شدند. ۲۸ تکرار آموزش و ۴ تکرار آزمون نیز حذف شدند. تشخیص هم‌پوشانی بر اساس متن نرمال‌شده با یکسان‌سازی ی/ک و فاصله‌ها و مستقل از نام موضوع و مجموعه است؛ بازنویسی‌های معناییِ مشابه را تشخیص نمی‌دهد. اولویت حفظ متن: آزمون، سپس اعتبارسنجی، سپس آموزش.

برای ParsiNLU علاوه بر ردیف‌های موضوع‌محور، فایل‌های سطح نظر با ۱٬۵۳۵ / ۱۹۰ / ۱۹۲ نظر ساخته می‌شوند. این فایل‌ها حضور سه موضوع مشترک را مشخص می‌کنند. هنگام ادغام طعم و کیفیت، مجموعهٔ احساس‌های موجود حفظ می‌شود و برچسب ترکیبی تازه جعل نمی‌شود. موضوع‌های خارج از این سه دسته در ارزیابی حضور، منفی فرض نمی‌شوند.

گزارش کاملِ بدون متن مشتری در [reports/benchmark_preparation.json](../reports/benchmark_preparation.json) شامل شمارش‌ها، نگاشت‌ها، فایل‌های حذف‌شده و checksum خروجی‌هاست. همهٔ امتیازهای آینده باید برچسب `out_of_domain` داشته باشند. پنج دستهٔ دما، تأخیر، پیک، حجم و اقلام ناقص در این منابع پوشش طلایی معتبر ندارند؛ عملکردشان فعلاً نامعلوم است.

## اجرا و نگهداری

```bash
uv sync --extra dev --locked
uv run snappfood-prepare-benchmarks
uv run pytest -q
```

داده‌های خام و آماده در `data/benchmarks/` نگهداری می‌شوند و وارد Git نمی‌شوند. اجرای مجدد فایل‌های کش‌شده را با checksum کنترل می‌کند و خروجی ثابت می‌سازد. ParsiNLU مجوز `CC-BY-NC-SA-4.0` دارد؛ مجوز بازنشر Pars-ABSA در مخزن مبدأ مشخص نشده است. گزارش و کد آماده‌سازی منتشر می‌شوند؛ متن منابع در مخزن این پروژه بازنشر نمی‌شود.

مرحلهٔ بعد: نمونه‌گیری ۱۰۰۰ نظر اسنپ‌فود و اجرای استخراج محلی با همین قرارداد. فایل‌های مرجع فعلی، آموزش یا اجرای LLM را انجام نمی‌دهند.
